## Recorrido recomendado para evaluadores

| Etapa | Qué buscar | Evidencia cuando exista |
|---|---|---|
| 01 · Abrir | Una entrada clara y navegación entendible | Captura real de inicio |
| 02 · Descubrir | Búsqueda o catálogo, si ya está disponible | Captura real y prueba de navegación |
| 03 · Evaluar | Ficha y metadatos, si están integrados | Ficha real y origen de los datos |
| 04 · Consultar | Entrada y respuesta del asistente | Video/GIF con interacción real |
| 05 · Validar | Correspondencia entre sugerencias y fuentes | Caso probado, limitaciones y resultado |

> **Regla de evidencia:** no grabar, publicar ni simular pantallas de funciones todavía no construidas. Señalar los pasos pendientes en lugar de presentar mockups como demo funcional.

## Especificación del microvideo de producto (pendiente)

Propuesta de **15–25 segundos, relación 16:9**, sin movimiento excesivo ni textos minúsculos. Duraciones orientativas, adaptables a lo implementado:

1. **0–3 s · Contexto:** portada del producto o entrada real.
2. **3–9 s · Descubrimiento:** navegación real disponible (omitir si aún no está implementada).
3. **9–15 s · Decisión:** mostrar una ficha real o, si no existe, pasar directamente al módulo disponible.
4. **15–22 s · Asistente:** consulta real y respuesta visible, si responde.
5. **22–25 s · Cierre:** «Explorá el prototipo» con URL de acceso.

**Formato recomendado:** GIF optimizado para vista previa silenciosa del README (idealmente compacto, sin datos personales). Para un video con sonido, alojar el MP4 o video en un servicio accesible y enlazar una miniatura; GitHub no garantiza la reproducción automática de videos HTML embebidos dentro del README. Dejar una imagen estática de respaldo accesible.

### Antes de reemplazar la portada conceptual por una captura

- [ ] Confirmar que la página abre sin inicio de sesión para un evaluador externo.
- [ ] Obtener aprobación del integrante responsable de la interfaz.
- [ ] Registrar fecha/versión de la captura y qué flujos se muestran.
- [ ] Probar escritorio y celular, incluyendo tamaño de tipografía.
- [ ] Evitar secretos, claves, correos privados y datos personales en las capturas.
- [ ] Comprimir el GIF sin sacrificar legibilidad.
- [ ] Mantener enlace real al prototipo aunque exista una grabación.
- [ ] Verificar que botones y documentos funcionen en GitHub sin sesión privada.
